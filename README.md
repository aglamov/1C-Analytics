# 1C Analytics

Универсальное приложение для iPhone и iPad, которое показывает управленческие показатели из 1С в удобном формате: быстрый обзор, детализация по группам и понятная динамика без необходимости открывать десктопные отчеты.

Первый сценарий проекта - дашборд "Образование" по задаче [SED-4884](https://tracker.yandex.ru/SED-4884). Описание подготовлено на основе документа `Показатели_Образование.docx`.

## Цель

Сделать адаптивный iOS/iPadOS-клиент для просмотра ключевых образовательных показателей из 1С:

- общее количество обучающихся;
- распределение обучающихся по гражданству: РФ и иностранные граждане;
- количество обучающихся по уровням образования;
- количество обучающихся очной формы обучения.

## Источник данных

Базовый источник для первого дашборда: регистр сведений 1С `(вуз). Обучение`, срез последних.

Подготовленный API:

`https://sed2.rudn.ru/DGU_HTTP/hs/DGU_APP_Mobile_Client/analitycs/`

Показатели группируются по уровням образования:

- БАК - бакалавриат;
- СПЕЦ - специалитет;
- МАГ - магистратура;
- АСП - аспирантура;
- ОРД - ординатура;
- Прочие - остальные значения.

## MVP

Первая версия приложения должна закрывать основной мобильный сценарий:

- экран подключения к серверу 1С или аналитическому API;
- список доступных дашбордов;
- дашборд "Образование" с карточками ключевых показателей;
- детализация показателя по группам;
- выбор даты или периода среза;
- обновление данных по запросу пользователя;
- индикация ошибок подключения, пустых данных и устаревшего среза.

Интерфейс должен одинаково аккуратно работать на iPhone и iPad: на iPhone давать компактный вертикальный сценарий, а на iPad использовать дополнительное пространство для сетки карточек, боковой навигации и параллельного просмотра списка и детализации.

## Технический фокус

Проект планируется как нативное универсальное iOS/iPadOS-приложение. На старте разумная архитектура:

- SwiftUI для интерфейса;
- Swift Charts для визуализации показателей;
- адаптивная верстка через size classes и responsive grid;
- `NavigationStack` для iPhone и `NavigationSplitView` для iPad;
- async/await для сетевых запросов;
- отдельный слой клиента 1С/API;
- модели показателей, независимые от конкретного транспорта;
- работа только с реальными данными подготовленного API.

## Запуск в Xcode

Откройте проект:

```text
1CAnalytics.xcodeproj
```

Схема приложения: `1C Analytics`.

Приложение использует реальные данные подготовленного API. Для доступа нужно создать локальный файл `Config/Secrets.xcconfig` на основе `Config/Secrets.xcconfig.example` и переопределить настройки:

```xcconfig
ANALYTICS_API_KEY = your_key_here
```

Ссылка на сервис хранится в `Config/Debug.xcconfig` и `Config/Release.xcconfig`:

```xcconfig
ANALYTICS_BASE_URL = https:/$()/sed2.rudn.ru/DGU_HTTP/hs/DGU_APP_Mobile_Client/analitycs/
```

API key не коммитится в git: файл `Config/Secrets.xcconfig` добавлен в `.gitignore`.

## Авторизация RUDN ID

Перед открытием дашборда приложение открывает страницу RUDN ID во встроенном окне:

```text
https://id.rudn.ru/sign-in?client_id=ed75cd5e-b477-4f3e-84b6-074608eee315&response_type=code
```

После успешного входа PASSPORT.RUDN начинает переход на зарегистрированный callback:

```text
https://sed.rudn.ru/DGU_DEMO/hs/DGU_APP_Mobile_Client/return_uri?code=<authorization-code>
```

Приложение перехватывает эту навигацию до выполнения GET, извлекает параметр `code`, закрывает окно входа и отправляет code на backend:

```http
POST /DGU_HTTP/hs/DGU_APP_Mobile_Client/auth/code
Content-Type: application/json
Accept: application/json
X-Auth-Key: <device-identifier>
X-Auth-Timestamp: <unix-timestamp-seconds>

{"code_analitic":"<authorization-code>"}
```

Backend возвращает данные сессии:

```json
{
  "token": "<token>",
  "username": "<username>"
}
```

`token` и `username` сохраняются в Keychain с режимом `WhenUnlockedThisDeviceOnly` и удаляются при выходе. Все последующие запросы к API, включая `/analitycs/`, содержат заголовки:

```http
X-Auth-Token: <sha1-signature>
Login: <username>
X-Auth-Key: <device-identifier>
X-Auth-Timestamp: <unix-timestamp-seconds>
```

`X-Auth-Key` содержит `identifierForVendor` текущего устройства в формате UUID.
`X-Auth-Token` содержит SHA1 в lowercase hex от конкатенации без разделителей: `X-Auth-Key + X-Auth-Timestamp + token`. Значение timestamp формируется в Unix-секундах и совпадает со значением заголовка `X-Auth-Timestamp`.

## Офлайн-режим

После авторизации приложение сразу читает последний дашборд текущего пользователя из локальной SwiftData-базы и параллельно пытается загрузить свежие значения из API. Каждый успешный ответ заменяет сохранённый срез. Если связи нет, ранее загруженные показатели остаются доступны и помечаются как сохранённые данные.

После первоначальной загрузки новые запросы выполняются по кнопке «Обновить». Ошибка ручного обновления не скрывает уже показанный дашборд. Кэш разделён по имени пользователя, поэтому данные одной учётной записи не показываются другой.

Дашборд открывается только после ответа backend со статусом `2xx` и успешного сохранения непустых данных сессии. Authorization code не сохраняется на устройстве. В Debug-сборке полученный code выводится в Xcode Console с префиксом `[RUDN ID]`.
